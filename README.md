# motion-craft

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Remotion](https://img.shields.io/badge/Remotion-4.0.538-blue.svg)](https://www.remotion.dev/)

motion-craft is a skill for AI coding agents that produces motion graphics videos in code, so you do not have to operate After Effects by hand.

Give the agent a topic or a product. It asks one round of questions, plans the video, builds it in Remotion, synthesizes the music and sound effects, and checks the final MP4 against a 5-gate QA report before handing it over. The quality target is motion graphics at an After Effects level, not a slideshow of still cards.

## Install

```bash
npx -y skills add EnamTiga/motion-craft -g -y
```

In Muse, copy the skill folder into `~/workspace/custom-skills/motion-craft/` instead, so the `references/`, `templates/`, and `scripts/` paths resolve from that folder.

## How it works

### The 8 phases

1. **Brief and assets.** The agent asks once about platform, duration, mood, and voice-over, then gathers references and licensed assets.
2. **Fact research.** Numbers and claims are sourced and labeled. Unverified claims are flagged, not dressed up as data.
3. **Concept and cues.** The agent writes the concept, the beat plan, the transition plan, and the music plan, then generates `cues.json` with `templates/make_cues.py`.
4. **Motion standards.** Scenes are designed against written motion standards, including the scene cycle and transition rules below.
5. **Technical setup.** The agent scaffolds a Remotion project, copies in the helpers, tests still frames, then renders.
6. **Audio.** Music and sound effects are synthesized from code. Voice-over is added in the mode chosen in Phase 1.
7. **QA.** The agent runs the 5-gate QA on the final MP4 and writes the evidence to `qa/report.md` and `qa/checks.json`.
8. **Delivery.** You get the MP4, a short report (8 lines at most), and an offer of specific revisions.

### One file holds all the timing

`cues.json` is the single source of timing. The Remotion composition, the audio scripts, the subtitles, and QA all read the same file, so picture and sound cannot drift apart. It is generated by `templates/make_cues.py` and checked against `templates/cues.schema.json`. Timing numbers are written in that one place, nowhere else.

### Motion rules

- Every scene follows a cycle: an entrance, a main action after the transition, development while the scene runs, and an exit or handoff to the next scene.
- Transitions vary. A video with 5 or more scenes uses at least 3 transition mechanisms, and the same mechanism never appears on two boundaries in a row.
- The `make_cues.py` validator enforces both rules. If a plan breaks them, you fix the plan. You do not bypass the validator.

### Music and sound effects

Music and sound effects are mandatory in every video, with or without narration. Both are synthesized from code with numpy and scipy (`templates/make_audio.py` reads `cues.json` and writes the mix). The final MP4 is normalized to -14 LUFS, plus or minus 1, with a true peak of at most -1.2 dBFS.

### QA: 5 gates, with evidence

Each gate ends in PASS, FAIL, UNVERIFIED, or NOT APPLICABLE with a reason. A check that could not be run is never recorded as a pass.

| Gate | What it checks |
|---|---|
| A | Brief, data, assets, and plans audited against the request before any render. |
| B | Still frames and frame bursts for every scene and transition, checked before the full render. |
| C | The final MP4 itself: codec, dimensions, FPS, frame count, full decode, black, freeze, and silence scans. |
| D | Narration, subtitles, and synchronization against `cues.json`. Only applies when a voice-over block exists. |
| E | Audio in the final MP4: loudness and true peak, stems present, ducking under narration, no clicks or clipping. |

## Voice-over modes

Pick one in Phase 1. The narration script is finished and approved before `cues.json` is locked, so the picture follows the sound.

| Mode | Audio source | Timing |
|---|---|---|
| A. No voice-over | None. On-screen copy carries the message. | From the plan in `cues.json`. |
| B. Your audio + WhisperX | A narration recording you supply. It is not regenerated. | WhisperX timestamps, or timestamps you supply after validation. |
| C. ElevenLabs TTS | ElevenLabs API, with a model and voice you choose. Draft approved first. | Alignment timestamps from the API response. If the endpoint gives none, each clip's duration is measured. |
| D. Use Muse | Muse TTS, synthesized per segment. Only offered inside Muse. | Each segment is measured with ffprobe; cumulative offsets set the segment boundaries. Subtitles sit at phrase level. No WhisperX, no API key. |

## Requirements

- An agent harness that supports skills, or an agent that can fetch and follow `SKILL.md` directly.
- Node.js and npm, with Remotion pinned at 4.0.538.
- ffmpeg and ffprobe for rendering checks, QA scans, and Mode D duration measurement.
- Python 3 for `make_cues.py`, plus numpy and scipy for the code-synthesized audio (`make_audio.py`).
- Mode B needs WhisperX unless you supply valid timestamps. Mode C needs your own ElevenLabs API key. Modes A and D need neither.

This skill is a craft and QA layer, not a Remotion tutorial. For Remotion API and caption rules, pair it with the official skill: `npx skills add remotion-dev/skills`.

## Repo layout

```text
SKILL.md                    Entry point: role, rules, phase router, voice-over modes
references/
  01-brief-and-assets.md    Phase 1: brief, assets, image quality
  02-facts-and-concept.md   Phases 2 and 3: fact labels, concept, beat plan, cues.json
  03-motion-standards.md    Phase 4: motion standards and anti-slop rules
  04-technical-setup.md     Phase 5: Remotion scaffold, render, fallback path
  05-audio-design.md        Phase 6: music, SFX, and voice-over modes A to D
  06-qa-gates.md            Phase 7: the 5 QA gates (A to E)
  07-delivery.md            Phase 8: delivery and report
  elements-ecosystem.md     External components and the adaptation checklist
  anti-patterns.md          Mistakes that have actually happened, in wrong/right form
templates/
  helpers.tsx               FPS, easing, spring, and scene helpers
  make_cues.py              Plan to validated src/cues.json
  make_audio.py             cues.json to synthesized music and SFX
  cues.schema.json          The cues.json contract
  cues.example.json         A complete cues.json example
scripts/qa_check.sh         Automated QA: metadata, decode, loudness, black, freeze, silence
```

## Prompt template

Install the skill, then send your agent a short brief:

```text
Make a video about <product or topic>. The target audience is <audience>. Here are my references:
<attach files, images, or video if any>
```

The agent asks one round of questions (platform, duration, mood, voice-over), then produces the video with animation, music, and sound effects, plus the QA report.
